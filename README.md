# 派单档期冲突：风险筛查与复核建议

## 我的判断

在 969 条派单中，927 条有已回传结果：825 条履约成功，102 条标记为“因档期冲突拒单或失效”，已标记样本成功率为 **89.0%**。另有 42 条（4.3%）结果空白，不能把它们当作成功，也不能拿它们评估派单风险。

最值得先验证的信号是档期数据较旧和剩余空闲档期很少。距档期最后同步超过 1 小时的已标记样本有 53 条，履约成功率为 **73.6%**；不足 1 小时的 874 条成功率为 **89.9%**。记录的空闲档期为 0–2 个时，80 条中有 16 条失败（失败率 20.0%）；11 个及以上时，624 条中有 59 条失败（9.5%）。这些是相关性，不足以证明同步过期或档期数量本身造成拒单。

按大区拆分后，失败率从华南一区的 7.9%（19/239，Wilson 95% CI 5.1%–12.1%）到华东一区的 13.7%（31/226，95% CI 9.8%–18.8%）。按服务品类拆分，从收纳整理的 8.6%（9/105，95% CI 4.6%–15.5%）到开荒保洁与深度保洁的 13.4%（分别为 17/127、13/97）。区间较宽且大多重叠，不能据此断言大区或品类之间存在稳定差异，也不建议直接给某一区域加严规则。

**根问题判断：派单决策对档期快照的新鲜度和可用余量缺少可靠的风险兜底。** 建议先将“档期同步距派单已满 1 小时，或剩余档期不超过 2 个”作为复核队列的候选触发条件：派单前触发一次轻量档期刷新/服务人员确认，再决定派出；先不要直接自动拦截。服务人员当日已完成单量与失败率的关系没有呈现一致的单调趋势，因此暂不把它纳入核心触发规则。

## 做了什么

提供一个仅依赖 Python 标准库的可复现脚本，统计结果缺失、档期同步时长、空闲档期、当日已完成单量，并输出大区/服务品类失败率的 Wilson 95% 置信区间。脚本还比较多组档期年龄和剩余档期阈值。保守基准规则在 927 条已标记结果中命中 128 条，其中 29 条失败（22.7%），覆盖 102 条失败中的 29 条（28.4%）。按派单特征计算，规则实际会触发 969 条中的 137 条，包含 9 条未回传记录；因此按每次复核 10 元计，复核成本为 1,370 元。若只把已标记的 29 条失败都当作可避免冲突，理论损失上限为 2,175 元，净上限为 **805 元**。

阈值敏感性分析中，样本内净上限最高的是“同步年龄至少 30 分钟或剩余档期不超过 3 个”：在已标记样本中命中 269/927，在全量特征记录中会触发 285/969，覆盖 68/102 条已标记失败（66.7%）。计入所有触发记录的 2,850 元复核成本后，理论净上限为 2,250 元。该规则在同一份数据上被筛选和打分，属于样本内比较，不能据此替换基准规则或预期真实收益；只说明值得在试点中与“至少 1 小时或不超过 2 个”并行比较。阈值越宽，复核量也越大。

这些净值都是乐观上限，不是收益预测：标签 0 合并了“档期冲突拒单或失效”，数据没有说明哪些确属可避免冲突，也没有实际复核成功率。对基准规则，盈亏平衡要求有效避免比例至少为 1,370 / (29 × 75) = **63.0%**。若按整数事件计算，至少要避免 19/29 条已标记失败（65.5%），此时模型净值仅 55 元。这里的“有效避免比例”同时包含失败标签中真正属于可避免冲突的比例，以及复核成功避免它们的比例。情景净值为：有效避免比例 0% 时 −1,370 元，25% 时 −826 元，50% 时 −283 元，60% 时 −65 元，75% 时 +261 元，100% 时 +805 元。9 条队列空白记录的复核成本已计入，但其潜在避免损失未计入，避免把未知结果当成可避免失败。

42 条空白结果在特征上并非完全均匀：基准队列空白率为 9/137（6.6%），队列外为 33/832（4.0%）；同步 1–4 小时组为 5/58（8.6%），不足 1 小时组为 37/911（4.1%）。因此只看已回传结果可能低估或高估部分分组的风险。极端边界检查（把空白全当成功或全当失败）下，总体失败率范围为 10.5%–14.9%，基准队列为 21.2%–27.7%，队列外为 8.8%–12.7%。这些是最坏情况边界，不是置信区间；队列内只有 9 条空白，不能据此确认缺失机制。

## 怎么证明有用

1. 先影子运行“60 分钟/2 个”与“30 分钟/3 个”两组候选阈值，记录各自命中量；再小流量做复核试点，不直接自动拦截。记录刷新/确认结果、最终履约、明确的冲突原因、复核耗时和用户等待。
2. 与未触发组或同风险层内的对照组比较冲突拒单率、履约率、复核成本、改派次数及等待时间，并按地区、服务品类检查差异；只有样本量足够时再解释细分差异。
3. 只有观察到净收益为正且履约与等待体验没有恶化，再逐步扩大范围。当前 CSV 只能支持离线筛查和阈值敏感性比较，不能证明线上策略效果。

## 复现

需要 Python 3，无第三方依赖。在仓库根目录运行：

```bash
python analyze.py
```

也可以传入另一份同结构 CSV：

```bash
python analyze.py path/to/dispatch_logs.csv
```

脚本将空白结果单独统计，只用 0/1 标签计算分组率、分组 Wilson 区间、候选规则命中和阈值敏感性；队列成本则按全量可触发记录计入。复现结果应包含 969 行、927 条已标记结果、825 条成功、102 条失败、42 条空白；基准规则 128 条已标记队列/137 条全量队列/29 条已标记失败；30 分钟/3 个阈值 269 条已标记队列/285 条全量队列/68 条已标记失败。

## 范围与假设

- 分析只使用本仓库提供的 `dispatch_logs.csv`；没有补造或外部数据。
- 时间差按带时区时间戳直接相减。候选阈值是为了形成可检验的运营假设，不是由实验确定的最优阈值。
- “已标记样本成功率”分母为有 0/1 结果的 927 条，不代表全部 969 条真实派单的最终履约率。
- 标签 0 包含冲突拒单或失效；题目给出的 75 元仅描述一次档期冲突拒单损失。因此经济估算按每条命中失败都属于该类且都能避免，明确视为理论上限。
